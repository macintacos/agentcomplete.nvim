# Editing the vimdoc (doc/agentcomplete.txt)

- **Target:** [`doc/agentcomplete.txt`](../../../doc/agentcomplete.txt), read by users as
  `:help agentcomplete`.
- **Reader of that file:** plugin users — the same audience as the README, but here they
  want depth. Be thorough and precise about concepts, configuration, and commands.
- **This reference is for:** agents (and maintainers) about to change the vimdoc.

## What belongs in the vimdoc

The full user-facing reference: how detection works for each agent CLI, every
`AgentComplete.Config` option (type, default, behavior), the blink and native backends,
only-source suppression, the project-root override, the `:Agent*` commands, the completion
sources/triggers, and the in-buffer diagnostics workflow. When a new option, command, or
behavior ships, this is where it gets documented in full — the README only links here.

## Format rules (`:help help-writing`)

- First line: `*agentcomplete.txt*<Tab>{one-line description}`.
- Define a tag with `*tag*` (right-aligned, prefixed `agentcomplete-…`); link with
  `|tag|`; options as `'option'`; code blocks open with a line ending in `>` (or `>lua` /
  `>vim` / `>sh`) and close with a `<` in column 1.
- Keep the main `*agentcomplete*` tag — `:help agentcomplete` depends on it. Update the
  CONTENTS list when you add or rename a section tag.
- Hold non-code lines to the modeline width (`tw=78`); keep the modeline last:
  `vim:tw=78:ts=8:noet:ft=help:norl:`.

## How to edit

Use the `/doc-coauthoring` skill when it is available. Keep the vimdoc and the README in
sync at the boundary: anything the README mentions in passing should have its full
explanation here.

## Verify

Help tags are generated by `:helptags` (plugin managers do this on install), so `doc/tags`
is gitignored — do not commit it. Confirm the doc still resolves headlessly:

```sh
nvim --headless --cmd "set rtp+=$PWD" -c "helptags doc" \
  -c "lua print(pcall(vim.cmd, 'help agentcomplete') and 'OK' or 'FAIL')" -c "qa!"
```
